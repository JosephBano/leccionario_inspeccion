```csharp
var builder = WebApplication.CreateBuilder(args);

    .AddApplicationLayer();

app.MapControllers();
app.Run();
```

## Regeneración de entidades

`Domain/Entities/` lo produce **EF Core Power Tools** por scaffolding desde `sigafi_es`.

```
Reverse Engineer → conexión sigafi_es → seleccionar tablas
  ✔ Use DataAnnotations: NO      (todo por Fluent API en el DbContext)
  ✔ Pluralize/singularize: NO    (los nombres salen tal cual de la tabla)
  ✔ Entity namespace:  Leccionario.Api.Domain.Entities
  ✔ Context namespace: Leccionario.Api.Infrastructure.DbContexts
  ✔ Context name:      sigafi_esContext
  ✔ Output: Domain/Entities  (PLANO, sin subcarpetas)
```

La configuración queda en `efpt.config.json`, que **sí se commitea** — es lo que hace
reproducible la regeneración por parte de otra persona.

Reglas:

1. **Nunca editar un archivo con la cabecera `<auto-generated>`.** Se pierde en la
   siguiente regeneración.
2. ¿Hace falta lógica sobre una entidad? Las clases son `partial`: crear
   `Domain/Entities/Partials/Matriculas.Logica.cs`. Aun así, se prefiere ponerla en un
   servicio de `Application/`.
3. Solo se scaffoldean las tablas que el sistema realmente usa (ver
   [`02-modelo-datos.md`](02-modelo-datos.md)), no las 300+ de `sigafi_es`.
4. Tras regenerar: `dotnet build && dotnet test` antes de commitear. Un scaffolding
   suele traer cambios de otras tablas que alguien tocó.

## Convenciones de código

### Nombres

| Elemento | Convención | Ejemplo |
|---|---|---|
| Clases, métodos, propiedades | `PascalCase` | `AsistenciaService`, `RegistrarAsync` |
| Campos privados | `_camelCase` | `_db`, `_logger` |
| Parámetros, locales | `camelCase` | `idAsignacion` |
| Interfaces | `I` + `PascalCase` | `IAsistenciaRepository` |
| DTOs | sufijo `Dto` | `RegistrarAsistenciaDto` |
| Async | sufijo `Async` | `ObtenerParalelosAsync` |

El dominio se nombra **en español** (`Asistencia`, `Paralelo`, `Distributivo`) porque es
el lenguaje del negocio y de la base. La infraestructura, en inglés
(`Repository`, `Service`, `Handler`). Es el mismo criterio de Bienestar — no mezclar
dentro de un mismo identificador (`AsistenciaRepository`, no `AttendanceRepositorio`).

### Reglas duras

1. **`async/await` de punta a punta.** Nada de `.Result` ni `.Wait()`.
2. **`CancellationToken`** se propaga desde el controller hasta EF.
3. **`AsNoTracking()`** en toda consulta de solo lectura.
4. **Nada de `SELECT *` implícito**: proyectar a DTO con `.Select(…)` antes del
   `ToListAsync()`. No traer entidades completas para leer dos columnas.
5. **Prohibido concatenar SQL.** Si hace falta SQL crudo, `FromSqlInterpolated`.
6. **Un método público, una responsabilidad.** Si pasa de ~40 líneas o tiene más de
   3 niveles de anidación, se parte.
7. **Nada de `catch (Exception) { }`.** Si se captura, se registra y se relanza o se
   traduce a una excepción de aplicación tipada.
8. **Sin números mágicos**: la ventana de 72 h, el tamaño de página y el work factor
   van en configuración o en constantes con nombre.
9. **`Nullable` habilitado.** Un warning de nulabilidad se arregla, no se silencia.
10. **Los controllers no consultan la BD.** Ni un `_db.` dentro de `Controllers/`.

### Comentarios

Se comenta el **porqué**, no el qué. Un comentario que repite el nombre del método
sobra. Se documenta con `///` lo público de `Application/` cuando la firma no basta
—especialmente las reglas de seguridad, como hace `PasswordService` en Bienestar.

### Logging

`ILogger<T>` con plantillas estructuradas, nunca interpolación:

```csharp
_logger.LogInformation("Sesion {IdSesion} cerrada por {Usuario}", idSesion, usuario);   // ✔
_logger.LogInformation($"Sesion {idSesion} cerrada");                                    // ✘
```

**Nunca loguear**: contraseñas, tokens, ni `idSigafi` sin enmascarar (es la cédula).

## Manejo de errores

Jerarquía de excepciones en `Application/Common/Exceptions/`:

```
AppException (abstracta, lleva Codigo y HttpStatus)
├── ValidacionException        → 400 VALIDACION
├── NoEncontradoException      → 404 NO_ENCONTRADO
├── ProhibidoException         → 403 (+ código específico)
│   ├── DistributivoAjenoException  → DISTRIBUTIVO_AJENO
│   ├── SesionCerradaException      → SESION_CERRADA
│   └── FueraDePlazoException       → FUERA_DE_PLAZO
└── ConflictoException         → 409 SESION_DUPLICADA
```

`ApiExceptionMiddleware` las traduce al formato de
[`04-contrato-api.md`](04-contrato-api.md). Los `500` nunca exponen el mensaje interno;
se registra con el `traceId` que sí se devuelve.

## Transacciones

Toda operación que escriba más de una tabla va en una transacción explícita:

```csharp
await using var tx = await _db.Database.BeginTransactionAsync(ct);
try
{
    await UpsertAsistenciasAsync(…, ct);
    await RegistrarHistorialAsync(…, ct);
    await _db.SaveChangesAsync(ct);
    await tx.CommitAsync(ct);
}
catch
{
    await tx.RollbackAsync(ct);
    throw;
}
```

## Configuración y secretos

- `appsettings.json`: valores no sensibles, se commitea.
- `appsettings.example.json`: la plantilla completa con los secretos **vacíos**. Se
  commitea y se mantiene sincronizada con las claves nuevas.
- `appsettings.Development.json`: valores reales. **En `.gitignore`.**
- En producción, variables de entorno (`ConnectionStrings__SigafiDb`,
  `JWTSettings__Secret`).

Un PR que agregue una clave de configuración **debe** agregarla también al
`appsettings.example.json`. El hook `pre-commit` bloquea cualquier commit con una
cadena de conexión o un secreto en un archivo versionado.
